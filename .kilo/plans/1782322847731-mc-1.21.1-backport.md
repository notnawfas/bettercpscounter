# Plan: Add MC 1.21.1 Support via Long-Lived Branch

## Goal
Create a separate long-lived branch (`mc/1.21.1`) that builds a dedicated jar for Minecraft 1.21.1, maintained alongside the existing `dev` branch (1.21.10–1.21.11).

## Strategy
Branch from current `dev`, then adapt all code that depends on post-1.21.1 Minecraft client APIs. The key breaking change is the input system refactor introduced in MC 1.21.2+ that replaced raw `int` parameters with wrapper types (`MouseInput`, `KeyInput`, `Click`, `Cursor`) and added `KeyBinding.Category.create(Identifier)`.

## Step 5: Fix `UltimatePvPUtilsClient.java`

### 5a: `KeyBinding.Category.create(Identifier)` → String category

**Current:**
```java
private static final KeyBinding.Category MOD_CATEGORY = KeyBinding.Category.create(Identifier.of("bettercpscounter", "keybindings"));
```

**Target (1.21.1):** The `KeyBinding.Category` class and `create(Identifier)` method don't exist. Use a plain string category:
```java
// Remove the MOD_CATEGORY field entirely

// In the KeyBinding constructor, change from:
new KeyBinding("key.bettercpscounter.open_config", InputUtil.Type.KEYSYM, GLFW.GLFW_KEY_F7, MOD_CATEGORY)
```

> In 1.21.1, `KeyBinding` constructor takes `String category` as the 4th parameter, not a `KeyBinding.Category` object.

### 5b: Remove `Cursor` import and usage

The `Cursor` class doesn't exist in 1.21.1. Remove the cursor management code from `render()` (or simplify to no-op). Cursor customization is cosmetic — acceptable to skip on the backport.

## Step 6: Fix `ModConfigScreen.java` (~790 lines — largest change)

### 6a: `Click` parameter changes

In 1.21.1, `Screen.mouseClicked()` signature is:
```java
boolean mouseClicked(double mouseX, double mouseY, int button)
```

Not:
```java
boolean mouseClicked(Click click, boolean always)
```

**Every method that receives a `Click` parameter needs to be refactored:**

- `mouseClicked(Click click, boolean always)` → `mouseClicked(double mouseX, double mouseY, int button)`
- `click.x()` → `mouseX` (already a double)
- `click.y()` → `mouseY` (already a double)
- `click.button()` → `button` (already an int)
- `mouseDragged(Click click, ...)` → `mouseDragged(double mouseX, double mouseY, int button, ...)`
- `mouseReleased(Click click)` → `mouseReleased(double mouseX, double mouseY, int button)`

### 6b: Cursor management removal

Remove the `cursorType` / `lastCursorType` fields and the cursor-setting block in `render()`. Optionally set `GLFW.glfwSetCursor` directly if hand cursor is desired.

### 6c: `mouseScrolled` signature

Check if `mouseScrolled` signature changed. In 1.21.1 it's typically:
```java
boolean mouseScrolled(double mouseX, double mouseY, double horizontalAmount, double verticalAmount)
```
This appears unchanged, but verify.

## Risks and Open Questions

1. **Exact dependency versions**: Fabric API, Loom, ModMenu, and Loader versions for 1.21.1 must be verified from Maven/Modrinth at implementation time. The versions in Step 2 are approximations.
2. **Yarn mapping names**: Method names like `onMouseButton` and `onKey` may have different Yarn mappings in 1.21.1. The implementation must verify the actual mapped method names by decompiling with the target Yarn version.
3. **`mouseDragged` signature**: May have different parameter order in 1.21.1. Verify during build.
4. **Java 21 compatibility**: MC 1.21.1 officially targets Java 21, so `JAVA_21` compatibility level should work. Verify Loom version supports it.
5. **Cursor management**: Dropping custom cursor support is acceptable for the backport. If desired, it can be reimplemented using `GLFW.glfwSetCursor` directly.
6. **`pack.mcmeta` `pack_format`**: May need to change for 1.21.1 (currently 75). Verify the correct format number.
